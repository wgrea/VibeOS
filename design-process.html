🖥️ Architecture: The Browser-as-OS Metaphor

1. The Design Token "Kernel"

Just as a low-level OS kernel manages hardware states, css/tokens.css acts as VibeOS's central configuration registry. Typography scales, neon accents, window borders, and surface materials derive directly from global variables. 

/* css/tokens.css */
:root {
  --neon-pink: #ff007f;
  --neon-cyan: #00f0ff;
  --bg-card: #181628;
  --border-outer: #2d284d;
  --radius-box: 16px;
}

2. Component Micro-Architecture (Layout Scalability)

Window shells, taskbar components, and application views remain decoupled. Triggering app views via HTMX unmounts and mounts partials on demand without resetting top-level system state.

⚙️ Core OS Systems & UI Translation

1. Window Lifecycle 🔄

  • Running (Focused): Active z-index layer, full bloom state.
  • Minimized (Waiting): Docked in taskbar with stashed coordinates.
  • Terminated (Closed): Unmounted from the DOM cleanly.

2. Inter-Process Communication (IPC) 📡

Modules communicate via custom DOM events and HTMX trigger pipelines, sending state focus updates between desktop widgets and taskbar indicators.

3. Directory Tree & Path Resolution 💾

Structured hierarchy using relative paths (e.g. aesthetics/vaporwave-timeline.html or spiritual-skills.html) to dynamically resolve sub-views.

🚦 Concurrency & Input Debouncing

To prevent UI race conditions during rapid user clicks or window dragging, interactive elements utilize HTMX throttling (hx-trigger="click throttle:300ms") to guarantee deterministic state flow.
